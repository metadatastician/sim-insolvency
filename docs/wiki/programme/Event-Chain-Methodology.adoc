== Purpose

Event Chain Methodology represents uncertain events which can alter programme
activities, gates, releases, quality or opportunity. It supplements ordinary
issues, dependencies, milestones, gates and risk management; it does not replace
them.

An event chain is:

----
initiating event
→ immediate consequence
→ triggered event
→ changed activity state
→ further event
→ programme outcome
----

== Event records

Every event records a stable ID, name, type, risk/opportunity classification,
description, trigger, early warnings, time window, qualitative confidence,
immediate effect, affected activities/state/gates/releases/cost/quality,
professional/authority/assessment impact, linked events, owner, mitigation,
contingency, recovery, residual exposure, evidence, review date and state.

Allowed qualitative values are `Very low`, `Low`, `Medium`, `High`, `Very
high`, and `Unknown`. Numerical probability is prohibited until empirical
delivery data justifies it.

Allowed operational states are `Watching`, `Triggered`, `Responding`,
`Contained`, `Materialised`, `Recovered`, `Expired`, and `Accepted`.

== Intervention rule

Every chain identifies the earliest observable indicator and at least one point
where intervention can break or soften the chain. An event issue stays open
while serious exposure exists; absence of occurrence is not closure evidence.

== Validation

Monthly review checks owner, evidence, rating, warnings, mitigation and affected
gates. A triggered event must update its issue, affected status page and gate
evidence. A material opportunity is governed with the same traceability as a
risk and cannot silently expand v1.
